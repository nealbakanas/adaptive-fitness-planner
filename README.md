# Adaptive Fitness Planner (Phase 1 prototype)

Single-page web app, no build step, no backend. All data lives in the browser's localStorage; back up from **Settings → Backup and data**.

## Run

```
python -m http.server 8765
```

Open http://localhost:8765. ES modules need to be served over HTTP; opening `index.html` as a file won't work.

To use it on your phone, host the folder on any HTTPS static host (GitHub Pages, Netlify, Cloudflare Pages), open it, and "Add to Home Screen" / "Install app". Data is stored per device and per URL, so pick one URL and stick with it.

After the first visit it works offline: `sw.js` fetches from the network first (so updates show up right away) and falls back to the cache when offline or when the network takes more than 2.5 s. When you change the file list, update `SHELL` in `sw.js`.

**Phone checklist once hosted:** install to home screen, check that it opens offline (airplane mode), Settings → Rest timer → *Test sound*, turn on *Notify when rest ends*, then *Test notification*, then start a rest and lock the phone.

## Layout

| File | Role |
|---|---|
| `js/seed.js` | Seed locations, families, exercises, schemes, slots, tier doses |
| `js/library.js` | Garage Strength Movement Library: new families, ~230 exercises with their videos, mobility drills (source list in `data/garage-strength-library.md`) |
| `js/store.js` | Load/save/migrate the single JSON state blob |
| `js/logic.js` | Pure rules: estimated max, dose crediting, slot scoring, scheme/exercise choice |
| `js/app.js` | Views, bottom sheets, rest timer, event handling |
| `js/goals.js` | Suggested weekly goals from history (pure functions) |
| `js/programs.js` | Fixed multi-week programs (Air Alert 2): chart, exercises, progress (pure functions) |
| `js/fitnotes.js` | FitNotes import: reads a `.fitnotes` backup with sql.js, then plain functions plan and apply the import |
| `sw.js` | Offline cache and background rest-over notifications |
| `tests.html`, `smoke.html` | Rules tests and a UI smoke test. Open them in the browser. Each uses its own storage key, so they never touch real data. `smoke.html?fitnotes=<url of a backup>` also runs a full import through the screens and undoes it |

## Rule decisions not spelled out in the PRD

- **Urgency** = priority × remaining quota ÷ days left in the week (the PRD's "× days left" would make slots less urgent as the week ends).
- **Time budget** comes from scheme minutes plus warmup (T1 +3 min), not fixed 12/20/40 thresholds. With the seeded schemes, 12 min fits a T1, 20 fits T1+T2, and 40 adds T3.
- **Estimated max**: Epley, sets of 10 reps or fewer only, best of the last 3 sessions with T1/T2 work for that exercise (technique and pump sessions don't count, so they can't drag loads down). Bodyweight moves add the bodyweight recorded with each set.
- **Tested 1-rep maxes** (Settings → *1-rep maxes*, the exercise editor, or *set your 1RM* on a T1/T2 block with no max): for 16 weeks after the day you enter it, a tested 1RM is a floor under the estimate, so lighter T2 work can't drag loads down and stronger logged sets still raise it; after that, or for an undated one (the old *starting max*), it's used only when there are no sets. For weighted bodyweight lifts it's the added load. The page lists your T1 goals' lifts, then T2, then other main lifts you've done in the last 12 weeks.
- **Week budget** (Week tab, under the goals): your usual week (workouts × minutes, from your last 4 weeks of check-ins unless you set it) against what your goals take, each goal session costed from your schemes (the middle scheme for its tier plus warm-up; T3s at three quarters, since they're superset partners half the time). It says how many more T2 or T3 sessions fit, or how far over you are, next to the GZCL guide per workout (1 T1, 1–2 T2, 2–4 T3). *Suggest from history* uses the same week (about one goal session per 15 minutes).
- **Target load** = e1RM × intensity for the scheme's reps-per-set (about 2 reps in reserve), clamped to the tier's range and rounded to the load increment. Swapping scheme or exercise recalculates it.
- **Progression (T1/T2)**: a loaded lift you did every prescribed set and rep of last time goes up by your load increment (Settings → You → Round loads to; 5 lb by default) the next time you do it at that tier with the same reps per set; one you came up short on repeats the load. The suggestion keeps last time's scheme for these lifts so they can progress (T3 and technique still rotate schemes). Kettlebell moves step to the next bell you own. With no like-for-like last time (a new rep scheme, or more than 8 weeks ago), the load comes from your e1RM as above. Each exercise card says why ("↑ 305 lb: you hit every rep at 300 on Oct 19" or "= 305 lb again: 2 reps short").
- **AMRAP last set**: *AMRAP last* on a loaded T1/T2 card makes its last set as-many-reps-as-possible. With every prescribed rep done, prescribed to double on that set (3-6 on a set of 3) is +5 next time, more than double (7+) is +10 (one or two load increments; kettlebells one or two bells); short is the same load. It stays on for that lift next time.
- **Exercise history**: *History* on any exercise card (or in the library) shows the max loads come from, what's next at each tier, and every session with that exercise: date, scheme, sets, best e1RM, and whether every rep was hit. *Full workouts* opens the search over whole sessions.
- **Removing an exercise**: the ✕ in the card's top corner, away from the set buttons, with Undo.
- **Slot credit**: sets auto-count when the exercise's family and the block's tier match a slot and, for T1/T2, the load is at least the tier's intensity floor × the pre-session e1RM. A slot earns one exposure per *day* whose counted sets meet the dose, so chunks across the day add up. Override any set in Week.
- **T1/T2 slots need a load × reps exercise at the location**, otherwise they're left out of the suggestion. Once any lift in a family has an estimated max, **T1 only uses lifts with one**, so a heavy squat goal waits for the barbell instead of becoming goblet squats at the Office (T2 can still use them).
- **Energy** = derived from fatigue and optional sleep. **"May split"** is a check-in toggle that favors many-set schemes.
- **Max reps per set** (optional, per exercise) is a hard filter on schemes. Seeded at 5 for clean variations and Nordic curls, 8 for glute-ham raises, 10 for reverse Nordics.
- **T3 schemes** aim for sets of 8-15 (3×15, 4×12, 5×10, 4×8; 5×10 on tired days). The high-energy volume bonus is for T1/T2 only, so 2×25 only comes up when about 5 minutes is all that's left. Hard bodyweight moves under a low cap get 6×5.
- **Rest timer**: rest = today's per-block setting (tap ⏱ on a block) > per-exercise override > scheme default. Starts on set check-off (toggle in Settings), stored as an end timestamp so it survives reloads and backgrounding. Beeps at 10s left and at zero, vibrates on Android, and holds a screen wake lock during sessions.
- **Tiers follow GZCL for loaded lifts:** T1 85-100% in sets of 1-3 (10-15 reps), T2 65-85% (20-30 reps), T3 10+ reps a set (30+ total). All editable under Settings > Tier doses. T1 schemes are all sets of 1-3. T2 also has 10×2 and 10×3 on a minute's rest: power work (cleans) uses them instead of sets of 5, and tired days lean on them (low reps, many sets). On a fresh day a strength lift never gets them on its own, so it keeps its sets of 5-10 (you can still pick them).
- **Explosive work and technique (athletic focus):** exercises can be flagged *explosive* (jumps, throws, Olympic lifts) and given a body *region* (lower, upper, whole body). Explosive work is **power** work when you're fresh: energy above 2.5 (fatigue 1-3; fatigue 3 with sleep 1 counts as tired) and no heavy T1 work in the same region since the start of yesterday. Explosive T1 work (cleans, jumps) doesn't count as heavy. Otherwise it becomes **technique** (the TECH tier): its own weekly goal, lower volume and load, never counted toward the power goal and never lowering an estimated max. Fresh days put explosive power blocks first; on tired or heavy days power goals wait (they aren't suggested) and technique goals get a boost. A power block that starts while not fresh offers a one-tap "Do it as technique".
- **Jumps are their own category** (the **JUMP** tier), not T2: jumps, bounds, hops and other unloaded lower-body plyometrics (`isJump` in `js/logic.js`), counted in contacts (reps; a timed or distance set counts as one). The tier is 12-30 contacts with short-set schemes (4×3 to 5×5, 3×8) on a minute's rest; a goal can set its own range (the seeded jumps goal is 12-20). **Jumps only come into a workout when you tick *Add jumps* at check-in**: then every builder (Suggest, focused workouts, Choose the mix) adds exactly one jump block, first in the workout, **to do during your warm-up: jumps never count toward the workout's time** (or the week budget), so the rest of the session is built as if they weren't there, toward your jumps goal when it's open (a jump from the library otherwise), in a lower-contact scheme when you're tired. With it off, a jumps goal is skipped ("jumps are off today") and no jumps are picked. Easy days give two light T2s, or one plus the jumps. Explosive work prefers sets of 1-3 and never gets the high-energy volume bonus. The v18 upgrade moves T2 jump goals, logged jump sets, open workouts and plans to JUMP, so this week's credit carries over.
- **Anytime exercises** get a boost on short check-ins (20 min or less) and split days.
- **Energy** at check-in is 1 wrecked … 5 fresh, so it points the same way as Sleep (1 poor … 5 great). It's stored as fatigue = 6 − energy.
- **T3s always come grouped**: T3s superset with each other in twos (alternate sets, rest after each round); an odd one out joins an existing T3 pair as a giant set, else a free T1/T2/technique block it doesn't compete with. Supersets on T1/T2 are optional (the idea row and ↔ Superset). ↔ Superset can also add a block to an existing pair to make a giant set. Unlink to do one on its own.
- **Supersets**: each T1/T2/technique block offers one T3 idea to do in its rest (Add, Other, No thanks), or tap ↔ Superset to pair it with any block or exercise. Pairs follow movement patterns read from exercise and family names: upper body pairs with its antagonist (pull-ups with triceps or push-ups, dips and presses with curls, rows or face pulls); lower body with its complement (squats and lunges with hamstrings/hips, hinges with quads, calves with either); core fits anything. Explosive main lifts (jumps, cleans) only get core or upper-body partners so the legs stay fresh. Ideas need no barbell, skip families with their own T1/T2 goal, and prefer an open T3 goal, then exercises you've done in the last 12 weeks. T3 pairs and giant sets use the same matching. A partner set doesn't restart the main lift's rest timer; "next" alternates between the two. A partner counts half its minutes toward the time budget.
- **Pause and more time**: Finish with sets left offers *Pause for later*; the paused workout waits on the check-in screen with Resume (paused workouts close at the end of the day like open ones). *+ Time* in the session header adds goal work that fits the extra minutes, from families not already in the workout.
- **Real rest** = time since the same block's previous set minus roughly the set's work (3 s a rep, or the set's time); gaps over 15 minutes count as breaks. Shown per block, for the session, in the finish message and in "Done today", next to the planned rest.
- **Timed and distance sets** (holds, sprints) count as one rep each toward a goal.
- **Warm-up sets** (T1 and T2 blocks on loaded lifts only): tap *+ warm-up* to add a row before the working sets, as many as you like. Rows start empty, with a ramp to your first working load as grey hints (40/60/80/90% for 5/3/2/1 reps); type your own numbers. A logged warm-up never carries its load into the working sets, starts a rest, counts toward a goal or real rest, feeds the estimated max or target loads, or counts as heavy work. Unlogged warm-ups are dropped at Finish, and when a block changes to T3/TECH. History shows them before the working sets.
- **Hold timer**: timed sets, and mobility moves dosed as a hold (not reps with a pause, like the cobra), have ▶ on each set row. It counts you in (Settings → Rest timer → *Get-ready countdown*, 5 s by default), times the hold with 3-2-1 beeps, and does each side in turn for per-side moves, with the same countdown between sides. When it runs out the set is logged with that time and the rest starts as usual. *+15* extends it, *Log* stops early and logs what you held, ✕ cancels. A timed set starts from the last time you logged for it (30 s the first time). It shares the bar with the rest timer and, unlike rest, doesn't notify in the background.
- **History** (Week → History): every workout and mobility session with something logged, newest first, 20 at a time, including imported FitNotes history. Each shows its exercises with tier and sets (repeats counted: `185×5 (×3)`). Search by exercise name, or open it from an exercise's editor in Library.
- **Deficit Romanian deadlift** is in Hamstrings (barbell) with a weekly goal: T2, once a week, medium priority. The goal names the exercise, so Nordics or leg curls don't stand in for it. Upgrading existing data reuses a Hamstrings family or a "Deficit RDL" you already have.
- **Freak Athlete Hyper Pro** (with its GHD pad and the Leg Developer attachment) movements are in the library as accessory work, needing the `hyper-pro` / `leg-developer` gear, which starts at the Basement: Nordic curl, glute-ham raise, seated and lying leg curl, back extension (45° and 90°), reverse hyper, hip thrust, Sorensen hold, belt squat, leg extension, reverse Nordic, calf raise, GHD sit-up and Trap 3 raise. Upgrading existing data reuses families and exercises you already have by the same name.
- **Garage Strength Movement Library** (their YouTube playlist, `js/library.js`): about 230 exercises, each with its video, in six new families (Snatch variations, Jerk & push press, Overhead press, Bench press & push-ups, Forearms & grip, Hips & glutes) and the existing ones. Snatch pulls go in Snatch variations and clean pulls in Clean variations, like the starter Clean pull. Snatches and jerks are explosive; jerks count as upper body, so they lead upper-body explosive days. Dowel drills are technique work, not explosive. Within a family they rank after the starter exercises (heavy lifts, then moderate, technique drills, accessories), so suggestions keep preferring what you already do. The nine mobility drills go in the mobility library. Equipment is a best guess per video; new gear (dowel, cable, med ball, sliders, hurdle, fat grips) is in the gear list but at no location, so those exercises stay out of suggestions until you tick the gear. No goals are added. Upgrading existing data reuses families and exercises you already have by the same name and only gives them the video if they have none. `data/garage-strength-library.md` lists every exercise with its default tier.
- **Every exercise has a role**: *main lift* (may be a T1/T2 strength lift), *power* (explosive T1/T2: jumps, Olympic lifts, throws), *accessory* (T3 only: curls, raises, flies, extensions, grip, calves, band work, bodyweight-only moves) or *technique drill* (no-feet, pause and dowel drills). The library's roles were reviewed exercise by exercise (`EXERCISE_ROLES` in `js/library.js`); your own exercises get a guess from the name, and you can change it in the exercise editor. Automatic T1/T2 picks (filling time, focused workouts, a family-wide T1/T2 goal) use only main lifts and power exercises, so the app never suggests a T2 clamp curl; when no main lift fits, the time goes to T3 work. A goal that names an exercise always gets that exercise, at its tier. A family-wide T3 goal uses an unweighted move (pull-ups, not weighted pull-ups 3×15). Grip curls have no movement pattern, so they're never read as a pull.
- **Automatic T2 lifts come from your T1/T2 goal families.** A family you only train as pump work (upper back, so chest-supported rows) is never picked as a T2 lift; when none of your goal families has a lift for a pattern at that location (pull-ups need the Office bar), that time goes to accessories instead. With no T1/T2 goals at all, any main lift can be picked.
- **Your chosen lifts stay the core.** Extra heavy work (a Heavy day's fill, a focused workout's main lift) only uses your T1 goals' lifts when you have T1 goals; if none suits the day (wrong half, gear, or heavy work there since yesterday), the main lift is T2 instead of a new heavy lift. Support (T2) work tries your T2 goals' lifts first, and power work (jumps, cleans) leads with a family you have a goal for, so cleans lead an upper-body explosive day until you add a jerk goal. Swap still offers every alternative.
- **Movement patterns**: "overhead press" or "military press" in a name or family counts as pushing before squat words, so a press in a split stance is a press. On a lower-body explosive day the second, lighter lift is from the same family as the first.
- **Archived exercises** stay in history but are left out of suggestions, swaps and pickers (Library → Show archived).
- Week starts Monday by default. Sleep is 1–5, stored as a number.

## Onboarding

A new install opens with a short setup (`js/onboard.js`); anyone can rerun it from Settings → **Set up again**. A new install starts with **nothing picked**: every lift and area is your choice (the starter goals are only behind *Skip*); *Set up again* starts from your own goals. The heavy and support steps have **+ Add an exercise** (the library's New exercise form): a loaded, non-explosive lift with gear at one of your locations is added as a main lift and picked on that step. Picks the steps don't show (a lift no location has gear for) are never saved. Steps: units and bodyweight; where you train (locations and their gear); your week (workouts × minutes); 2–3 heavy lifts (T1) from the main lifts your gear allows, grouped by squat/hinge/push/pull, each with times a week; support lifts (T2) and power work (jumps, cleans, snatches, jerks); accessory areas (T3); tested 1RMs for the lifts you picked; and a review with the week budget. Heavy and support picks become goals naming the lift, power and accessory picks family-wide goals, and an Olympic lift family also gets a technique goal. It starts from your current setup (the starter goals for a new install). Saving replaces goals, locations and the week, sets the maxes, and keeps a copy: **Undo** in the banner puts everything back. Logged history is never touched. *Skip* keeps the starter setup; *Import from FitNotes first* goes to the import. Data saved before onboarding existed counts as already set up.

## Updates

The service worker (`sw.js`) loads files from the network first, always revalidating (never the browser's 10-minute cache), and falls back to the saved copy after 2.5 seconds on a slow signal. When the newer copy arrives after that, the page shows **A newer version of the app is ready. Reload**. A home-screen app that resumes without reloading checks for a new version each time you come back to it, and reloads itself after 30 minutes away. **Settings → App → Get the latest version** clears the saved files and reloads fresh (your data stays), and shows which version you have (the worker's cache name, `afp-vN`). **Bump `CACHE` in `sw.js` with every release** so a new worker installs and the version shown changes.

## Data safety

- If saved data can't be opened (for example an upgrade step fails), the app keeps it untouched, pauses saving, and shows a message with **Copy the saved data** and **Start fresh**. It never saves the starter data over it.
- If a save fails (storage full or blocked), a message stays at the top of every tab until a save succeeds.
- The FitNotes import takes a snapshot first; **Backup and data → Undo last import** puts it back.
- **A second copy on the device** (`js/vault.js`, IndexedDB database `afp-vault`): every save also writes the whole data there (2 seconds later, and when the page is hidden). If the browser clears localStorage but not IndexedDB, the data comes back at startup with a banner. If a localStorage write failed and the second copy is newer, the app offers it (**Use it** / **Ignore**; a snapshot keeps it either way). If the saved data can't be opened, the load-problem banner adds **Use the backup copy from <date>**. Where IndexedDB is missing or blocked, the app behaves as before.
- **Snapshots**: one **daily** snapshot on the first save of a day with logged sets (newest 14 kept), and one before anything replaces your data (FitNotes import, setup finish, pasting or choosing a backup, restoring a saved copy, Erase all data; newest 10 kept). **Backup and data → Saved copies on this device** lists them (date, why, workouts and sets); tap one to go back, with Undo.
- **Backing up off the device**: **Save backup to…** opens the phone's share sheet (Files, iCloud Drive, Google Drive, email) or downloads a file on a computer; only a finished share or download counts as a backup. The reminder shows after 3 finished workouts, or 7 days with one, since the last one (**Not now** waits 3 days). The same screen shows whether the browser has agreed to keep the data (`navigator.storage.persist()`, asked after setup and when the screen opens), when the copy on this device was saved, and the last backup off it.
- Saved data carries a `savedAt` stamp and `version` 19; `tests.html` covers the rules and the vault, `smoke.html` the screens, and `recovery.html` simulates a cleared browser across real page reloads.

## Cloud backup (Supabase)

Optional. **Backup and data → Back up to your account** signs you in by email (a link, or a 6-digit code: no password) and keeps your data in your own row of a Supabase project (`js/cloud.js` for the server calls, `js/sync.js` for what to do, `js/merge.js` for combining two devices). The project URL and publishable key are in `js/cloud-config.js`; both are public by design, and row-level security lets a signed-in user touch only their own row.

**One-time setup in the Supabase dashboard:**
1. **SQL Editor** → run `supabase/schema.sql` (safe to run again).
2. **Authentication → URL Configuration:** set the Site URL to where the app is hosted and add the same address to Redirect URLs.
3. **Authentication → Email Templates → Magic Link:** add `{{ .Token }}` (for example a line "Or type this code: {{ .Token }}"), so the email carries the code. Needed on an iPhone home-screen app, whose links open in Safari instead of the app.
4. The built-in email sender allows only a few emails an hour. For more, add your own SMTP under **Authentication → SMTP**.

**How it syncs:** one row per user with a revision number. After you stop saving for 10 seconds, when the network returns, and when you come back to the app, the device compares itself with the account: nothing changed → nothing sent; only this device changed → push; only the account changed → pull; both → merge, then push. A push only lands if it names the revision it was based on, so two devices can't overwrite each other: the loser merges and retries.

- **Asks before restoring.** The first time a device meets an account that has data (a new phone, a cleared browser, signing back in), and whenever a device looks erased while the account has data, a sheet offers **Use the account's copy**, **Merge both** or **Keep this device's**, and nothing changes until you choose. Every choice first snapshots what's here; the account's copy is kept as a saved copy too.
- **Merging is three-way** against the data as of the last sync (kept in the on-device vault): records are matched by id; a change on one side is kept; a record deleted on one side stays deleted unless the other side edited it; real conflicts go to the side saved most recently. Settings merge key by key. A device's running rest timer never syncs.
- **Safe by default:** an account copy from a newer build is left alone until this device updates; offline just waits; signing out keeps your data (signing back in asks again).
- **Scale:** the whole data is one row of about 300 KB per user, fine for a few users. Records are id-keyed and the sync code is isolated, so moving to per-record sync (only what changed) later touches `js/cloud.js`, `js/sync.js` and `js/merge.js`, not the app.
- Tests never reach the real project: test pages set `AFP_SUPABASE_URL` to a fake address and `js/fake-supabase.js` answers in memory.

## Mobility

Mobility lives outside the strength framework: its own exercises, routines and sessions (`js/mobility.js`), with no tiers, weekly goals or estimated maxes, and it never counts toward strength goals.

- **Exercises** have body parts (Hamstrings, Hip flexors, Adductors, Glutes, Quads & knees, Calves & ankles, Spine, Thoracic, Shoulders, Lats), a dose (sets × reps or hold, ranges, each side, tempo), rest, what to log per set (reps, hold time, load, and one custom field such as "Deficit (cm)" or "Knee-to-floor (cm)"), cues, a YouTube search phrase and history notes. Add and edit them in Library → Mobility.
- **Routines** (Plans tab) are ordered lists of mobility exercises. The four you've been running (Long & Strong, All the Width, Bend Don't Break, Primal Roots) are included, with your week 1–2 notes as each exercise's history.
- **Mobility sessions** start from the check-in screen: a routine, or *Pick body parts*. **+ Mobility** adds moves to a strength workout the same way.
- **Picking by body part**: choose up to 3; for each part the move you've done least recently is ticked (moves covering more of the picked parts rank first). Each set shows last time's numbers and note; loads and the custom field prefill from last time.
- Logging a set starts that exercise's rest. Finishing keeps only what you logged. The Week tab shows mobility sessions and which body parts you've covered.

## Lean and filling the time

- **Lean** (check-in: Either, Upper body, Lower body) is how your body feels today. Goals for that half score ×1.5 and goals for the other half ×0.5 (core and whole-body work like cleans are neither), so the other half only comes up when it's much more urgent. It also steers what fills the extra time, and puts that half's two focused workouts first (highlighted) on check-in and in the offer when goals run thin; the other half stays one tap away.
- **Suggestions always use the whole time block, even when every goal is done.** Once the open goals are picked, whatever time is left is filled from your library (`fillTime` in `js/logic.js`): on a Heavy day with no heavy lift in the session yet (and not tired), one of your T1 goals' lifts (the one each goal would use here), trained heavy least recently, whose half of the body has had no heavy work since yesterday (with no T1 goals, any lift you've loaded, i.e. with an estimated max); then T2 strength lifts until the session has two, or on a fresh day (energy 4-5, not Easy) three from 45 minutes and four from 75 (goal ones count; jumps and cleans are power work and don't). T3s are capped per session at 4 (two supersets) up to an hour, then one more per 15 minutes, goal ones included; past the cap, leftover time goes first to more sets, then on a fresh day to another T2, and only then to more T3s, so the time is still filled. Easy days' T2s are never stretched to longer schemes. On an **Easy** day it's still 1-2 T2s, lighter: a jump block first if the session has none and you aren't leaning upper-body (T2 when fresh for power, else high-volume T3), then T2 lifts until there are two T2 blocks in all (jumps count), in the shorter, lower-volume schemes (3×8, 4×6). Every strength lift goes to a movement pattern that has no strength lift in the session yet: the half you lean toward first, then the other half, the pattern trained heavy least recently first (T2s skipped on Easy or with under 15 minutes left); then T3 accessories in supersets on that half's rotation, then the other half's if that one runs out. Pairing T3s into supersets frees time, which goes to another accessory while one fits; the T3s are then grouped from scratch, and if a workout would run over, the last accessory is dropped. When new families and movements run out and time is still left, another exercise from a family already in the workout comes in (a second core or upper-back move), never one that's already there; the rotation carries on where it stopped, so these alternate. A workout holds about one exercise per 5 minutes (at least 10), so every check-in length up to 90 minutes, Easy days and focused workouts included, is filled to within a few minutes. *+ Time* sees the whole session, so it never adds a second heavy lift or repeats a pattern's strength lift. Support lifts come from families with a T1/T2 goal first (front squats before leg extensions, chin-ups before curls) and aren't a T1 goal's own lift when another fits. Weighted pull-ups and dips (dip belt) are never T3 filler. *How this was built* lists them. Anything that matches a goal still counts toward it, and *+ Time* fills the same way.
- **Wrecked days and Regenerate.** At energy 1-2 a suggestion has one T2 at most (goal ones count), and the rest of the time goes to T3 supersets; an urgent heavy goal can still take the T1 slot. On a suggested or focused workout, *Regenerate* rebuilds what you haven't logged with the equal-ranked library picks rotated, and family-wide accessory (T3) goals rotate through the family's closest accessories (goals that name an exercise and your T1/T2 lifts stay the core; logged work stays). Tap it again for another take; if your goals' lifts fill the whole session it says so and suggests Swap or Choose the mix.
- **Choose the mix.** On the check-in, *Or choose the mix* takes how many T1, T2 and T3 blocks you want (`buildMix` in `js/logic.js`). Open goals fill each tier first, for the half you lean toward; the library fills the rest. The counts are what you asked for, so nothing tops up beyond them, and a T3 that doesn't fit the time is dropped with a note. Regenerate works on a mix too.
- **Time** is each scheme plus its warm-up (T1 5 minutes for the ramp, T2 2, technique 1) plus a **changeover** per exercise for moving, loading and setting up (2 minutes by default; Settings → You → Changeover). Jumps take none (warm-up). Superset partners count at half, as the session header does. Fresh days aim for 3 T2 lifts from an hour and 4 from 90. When the library runs out before the time does, the T2 and T3 work gets more sets (3×15 → 4×12, 3×10 → 5×5), cheapest step first; explosive and T1 work keep their schemes. On a tired day a step never raises the reps per set (6×4 can become 10×2, not 5×5); on other days it never moves a strength lift into 10×2 or 10×3.
- Lifts that are a T1/T2 goal's own exercise (weighted pull-ups, weighted dips, back squats) aren't used as T3 filler.

## Focused workouts

For days when your weekly goals are (nearly) done but you have time and energy. Check-in has **Upper body**, **Lower body**, **Upper body + explosive** and **Lower body + explosive**. When the open goals fill under 60% of your time, the suggestion still fills it from the library and offers the same four, replacing whatever isn't logged yet. Built from your whole library at the location (`buildFocus` in `js/logic.js`), not just open goals, and anything that matches a goal still counts toward it. Every focused workout fills the time the same way as suggestions.

- **Lower body + explosive**: jumps first (JUMP) if you ticked *Add jumps*, then a clean variation (T1) and, with 30+ minutes left, a second, lighter one in sets of 1-3 (T2). Then a couple of accessories, lower back, legs and core first (GZCL lower-day style), then a T2 lift if there's time, then more accessories. Not fresh (tired, or heavy lower-body work since yesterday): one technique block (a clean if there is one) instead of the power work.
- **Upper body + explosive**: one explosive exercise for the upper body first, else a clean, at power (T1 for cleans, T2 for throws) when fresh or technique when not, then the upper-body lifts below.
- **Main lift** (not on explosive lower days): from the movement pattern trained heavy least recently (upper: push or pull; lower: squat pattern or hinge; for a T1 lift, the one whose last T1 work is oldest, so T2 work doesn't hide a pattern that hasn't been heavy all week), a loaded lift you do, T1, or T2 when you're tired, picked Easy, or did heavy work in that region since yesterday. **Second lift**: the other pattern at T2 (skipped on Easy).
- **Accessories** (T3, no barbell setups): a rotation for the region (upper: pull, push, pull, core, push; lower: lower back, squat pattern, core, hinge, calves), repeated until the time is used, the ones you do but haven't done for longest first, grouped into supersets as usual. Once every family is in use, another move from a family already in the workout can come in if it's a different movement (triceps after curls). *How this was built* explains each pick; *+ Time* adds more accessories.

## Programs: Air Alert 2

An optional 12-week jump program, kept separate like mobility: it never counts toward weekly goals, estimated maxes or the heavy-work readiness rules. Start it from Plans → Programs (or the Programs row on check-in).

- **The chart** (TMT Sports' Air Alert II): leap ups, calf raises (each leg), step ups, thrust ups and burnouts, Monday to Friday, the same workout every day of a week, from 2×25 / 2×10 / 2×10 / 2×15 / 1×100 in week 1 to 2×200 / 2×70 / 2×40 / 2×100 / 1×1200 in week 12. Thrust-up and burnout cues are written for the app (the source sheet was cut off).
- **Progress**: check-in shows *Week 3 of 12, day 2 of 5* with today's doses and *Start today's session*. A session is logged like mobility (reps prefilled, 1:00 rest, notes, last time). Finishing one with anything logged moves to the next day; after day 5, the next week. On the program page you can restart the week, jump to any week, or stop (sessions and verticals stay). After 7+ days away it suggests repeating a week; on weekends it reminds you program days are Monday to Friday.
- **Progress chart**: the 12-week table with days done per week and a vertical jump entry per week (in, or cm with kg units), like the sheet's progress chart.
- Sessions show in History (*Air Alert 2 · week 1, day 1*) and as a line on the Week tab, not in the mobility body-part summary.

## Suggested weekly goals

Week → **Suggest from history** (also offered after a FitNotes import). It looks at the last 12 weeks (26 if that's thin) and proposes goals for review: untick or change any of them, then **Replace my goals** or **Add to my goals**, with Undo.

- **Which movements and how often** come from your history: families trained at least every few weeks; times per week = workouts with that family ÷ weeks (1-3).
- **Tiers and rep ranges follow GZCL**, not your recent numbers: explosive loaded lifts (cleans) → T1 power, high priority; jumps/sprints → a JUMP goal at about 12 contacts a session, high priority; other loaded lifts → T1 if you do them heavy (3+ workouts and a third of them), else T2; everything else → T3.
- **The main explosive lift also gets a technique goal** (once a week) for tired days.
- **About one heavy (T1) lift per workout**: explosive lifts first, then lower body. Extra heavy lifts become T2 support work.
- **Chest and shoulders** are always included, once a week at low priority.
- **The week has to fit**: about 3 goal sessions per 45-minute workout; accessories are unticked first, explosive lifts last.

## FitNotes import

Settings → Backup and data → **Import from FitNotes**. Pick the `.fitnotes` backup; it's read on the phone with sql.js (kept in `vendor/sql.js`, version 1.14.2, about 0.7 MB, loaded the first time you import) and never uploaded.

- **Window**: the last 1, 2 (default) or 4 years. Two years of your history is about 5,700 sets and 1.3 MB of saved data.
- **Review**: exercises with 3+ workouts in the last year are listed with best guesses (existing exercise or new; family; how it was logged; body region; explosive; equipment) and can be changed. Older ones come in archived.
- **Matching** uses names and how the sets were logged, so FitNotes "Pull Up" with added weight goes to *Weighted pull-up*, not the reps-only *Pull-up*. An unused starter exercise can switch how it's logged to match the history.
- **Conversion**: kg to lb (rounded to 0.5). On bodyweight exercises 0 lb and 1 lb mean bodyweight; on loaded lifts they mean no weight was entered (left out of the estimated max). 0-rep sets are kept as misses. Sprint distances typed in the weight column become distance.
- **Tiers** are guessed per set from GZCL (1-3 reps at 85%+ of the lift's best in the previous 12 weeks → T1, up to 8 reps at 65%+ → T2, else T3; jumps and sprints → JUMP).
- **Usual choice per family** becomes the exercise you did most in the last year, unless you've been logging the current one in this app.
- **Repeat imports** skip sets already imported (stable ids) and reuse earlier choices. If you log the same workout in both apps, it counts twice.
